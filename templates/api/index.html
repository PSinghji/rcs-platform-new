Authentication flow
  1. Send your username and password to POST /api/v1/auth/token.
  2. Store the returned access token securely.
  3. Create a template, check its approval status, then list approved templates to obtain a valid template_id.
  4. Create a campaign with JSON parameters or upload a CSV/XLSX audience, then monitor status and download the report.
curl -X POST "{{ request.base_url }}api/v1/auth/token" \
  -H "Content-Type: application/json" \
  -d '{"username":"YOUR_USERNAME","password":"YOUR_PASSWORD"}'

Simple and dynamic JSON examples
Create a simple template
curl -X POST "{{ request.base_url }}api/v1/templates" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Simple Service Update",
    "template_type": "plain",
    "content": {"plainText": "Your service request has been completed."}
  }'
Create a dynamic template

Use placeholders in any string field. The API automatically detects and stores the variable names.

curl -X POST "{{ request.base_url }}api/v1/templates" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Dynamic Coupon Offer",
    "template_type": "plain",
    "content": {
      "plainText": "Hello {% raw %}{{name}}{% endraw %}, use {% raw %}{{coupon_code}}{% endraw %} before {% raw %}{{expiry_date}}{% endraw %}."
    }
  }'
Send a simple JSON campaign
curl -X POST "{{ request.base_url }}api/v1/campaigns" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "campaign_name": "Simple November Campaign",
    "template_id": "APPROVED_TEMPLATE_ID",
    "numbers": ["9876543210", "+919123456789"]
  }'
Send a dynamic JSON campaign without CSV

Each recipient supplies a variables object. Its keys must match the approved template placeholders exactly.

curl -X POST "{{ request.base_url }}api/v1/campaigns" \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: campaign-request-20261112-001" \
  -d '{
    "campaign_name": "Personalized November Campaign",
    "template_id": "APPROVED_DYNAMIC_TEMPLATE_ID",
    "recipients": [
      {
        "mobile": "9876543210",
        "variables": {
          "name": "Asha",
          "coupon_code": "SAVE20",
          "expiry_date": "30 November 2026"
        }
      },
      {
        "mobile": "+919123456789",
        "variables": {
          "name": "Ravi",
          "coupon_code": "SAVE10",
          "expiry_date": "30 November 2026"
        }
      }
    ]
  }'
Campaign creation requirements
  • Call GET /api/v1/templates/approved and use the required template id as template_id.
  • For JSON campaigns, use numbers for simple messages or recipients[].variables for per-recipient dynamic values. No CSV file is required.
  • Dynamic variable keys must match template placeholders. Missing values are rejected before campaign submission.
  • The server automatically generates an idempotency key for campaign creation. Supplying an optional Idempotency-Key is supported when your integration needs to retry the same request safely.
  • CSV, TXT, or XLSX upload supports up to 500,000 unique valid Indian mobile numbers and a 20 MB file. XLSX files must contain a Mobile column in the first worksheet.
  • Users can monitor and download only their own campaigns. Administrators can access any campaign by ID.
